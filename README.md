# 日迹 · Hoshino’s Agenda

以项目日历、项目总览和素材库管理项目进展的 WebApp。支持周期重复与复制事项、无日期事项、项目与日期筛选、事项标题搜索、事项完成状态、可选 Markdown 描述与逐事项描述加密、描述内 @ 引用、图片和文件附件，适配桌面与手机。

输入邮箱即可打开对应的数据空间。邮箱会去除首尾空格并转换为小写；目前无需密码或验证码，任何输入同一邮箱的人都能读取和修改该空间。浏览器仅记住邮箱；项目、事项、素材元数据和关联保存在 Cloudflare D1，文件保存在私有 R2 存储桶。

## 本地启动

工具链版本由仓库管理：**Bun 1.3.14**、Linux x64 / arm64 的 **Node.js 22.23.3** 都作为依赖安装到 `node_modules`，版本及完整性由 `bun.lock` 固定。容器只需提供可用于首次安装的 Bun、网络及系统库；无需全局安装 Node.js 或 npm。以下命令均在项目根目录执行。

```sh
bun install --frozen-lockfile
bun run bun --version
bun run node --version
bun run db:migrate
bun run dev
```

打开 <http://localhost:3000>。前端为 Nuxt SPA，浏览器通过同源 `/api/*` 请求数据；Nuxt 开发服务器将这些请求代理到本地 Worker（8787）。访问 <http://localhost:3000/api/health> 返回 `{"ok":true}` 表示代理及 Worker 已启动，数据库是否可用由实际数据请求确认。

`bun run` 会优先使用仓库 `node_modules/.bin` 内的工具，根脚本和 workspace 子进程均使用本地 Node.js / Bun；容器全局的 `bun --version` 可以不同。依赖安装后需要用固定版本重装时执行 `bun run bun install --frozen-lockfile`。不要从其他机器复制 `node_modules`，应在目标环境重新安装。Linux Node 二进制面向 glibc 环境；其他平台目前仍需自行提供 Node.js 22.12+。

- `db:migrate` 初始化本地 D1；开发数据保存在 `apps/api/.wrangler/state/`。
- Wrangler 开发模式提供本地 R2 模拟，无需先创建远程桶；本地素材与远程桶互不影响。
- `dev` 同时启动 Web 与 Worker，保留 Nuxt 热更新，无需预先构建；在终端按 Ctrl+C 停止。
- 单独启动：`bun run --filter @agenda/web dev` 或 `bun run --filter @agenda/api dev`。
- 前端固定使用相对路径 `/api`，不再使用 `NUXT_PUBLIC_API_BASE`；旧 `.env` 或部署环境中的这个变量可删除。
- `ALLOWED_ORIGINS` 默认为空，同源请求自动允许；本地 Worker 的 `dev` 脚本临时允许 3000 端口的 localhost/127.0.0.1 Origin，供开发代理使用。
- 要预览实际单 Worker 部署，运行 `bun run build && bun run preview`，打开 <http://localhost:8787>。预览复用本地开发 D1，先执行 `bun run db:migrate`。

## 使用方式

1. 输入邮箱，创建项目并选择颜色。侧栏项目右侧的「…」菜单提供「转到项目总览」（同时筛选该项目）、「编辑」、「上移 / 下移」。点击「我的项目」旁的排序图标可打开统一排序弹窗：拖动项目手柄（桌面和手机均上下拖动），或聚焦手柄后按上下方向键；点击「保存排序」统一保存，取消则丢弃调整。顺序保存到云端，侧栏、总览和事项表单共用，刷新后保留，新建项目追加到末尾。保存失败保留原顺序并显示错误；旧页面排序提示冲突时，点击同步后重试。
2. 在 header 面包屑中切换「项目日历 / 项目总览 / 素材库」。日历提供「月 / 周 / 日」视图：桌面默认月视图，宽度不超过 600px 的手机默认周视图；刷新后恢复对应默认值。周视图按周一到周日纵向排列，每天的事项标题横向排列、空间不足时换行，左右按钮按周导航，顶部统计当前周。点击日期在下方查看当天详情；日期选择可直接跳转到其他周。总览按项目展示所有日期的事项（含空项目），默认隐藏已完成事项及全部完成的分组。顶部显示「未完成 / 已完成」数量，点击「已完成」及其数字切换显隐，展开时以粉色高亮；统计数量不随显隐变化。事项先按目标日期、再按添加时间从早到晚排列，未设目标日期的事项排在最前。总览及日历详情的事项卡片显示本地时区的添加日期；左侧项目筛选对日历和总览有效，素材库展示当前邮箱的所有素材。切换时保留当前筛选、已完成显隐状态、日历日期和所选日历视图。

   总览支持「全部日期 / 时间段 / 无日期」三种日期筛选，依据事项安排日期而非添加日期。「时间段」打开日历选择起止日期，点击「应用」后生效，包含起止当天；只选一个端点或关闭小窗不会改变现有筛选。「无日期」仅查看未安排日期的事项。统计与项目内数量按当前项目和日期筛选计算，已完成显隐不影响统计；启用日期筛选时隐藏无匹配事项的项目，点击「清除筛选」恢复全部日期。切换项目、日历和素材库时保留日期筛选，刷新或切换邮箱后恢复全部日期。引用跳转时仅清除会隐藏目标的日期筛选，并自动显示已完成目标；保存无日期事项后，原时间段筛选恢复全部日期，原无日期筛选继续保留。

   在总览「搜索事项标题」中输入关键词，按标题实时进行包含匹配，忽略大小写和关键词首尾空白，标点按普通文本匹配；只搜索标题，加密描述无需解锁。搜索可与项目、日期筛选及已完成显隐组合，顶部和项目统计同步按匹配结果计算，无匹配项目隐藏。点击输入框右侧的清除按钮仅清除标题搜索并保留其他筛选。同步及切换项目/工作台视图保留关键词，刷新或切换邮箱清空。引用跳转时，仅清除会隐藏目标的标题搜索或日期筛选；无日期事项保存成功后，若新标题不匹配当前关键词，则清空搜索以显示保存结果，保存失败保留关键词。
3. 在日历或总览项目组中点击「+事项」，填写必填标题和所属项目。日历中默认选中日期，总览中默认未设日期；点击日期框选择日期，点击框内右侧的「×」清除为「未设日期」，再次点击日期框即可补充日期。清除按钮支持键盘操作，清除后焦点返回日期框。无日期事项计入总览及侧栏数量，不计入月 / 周 / 日日历及对应统计；清除日期并保存后自动打开总览。
4. 点击事项左侧方框切换完成状态；点击标题或编辑按钮可修改事项。可选填多行描述，详情和悬浮卡片支持标题、粗体、斜体、删除线、列表、引用、代码与链接等基础 Markdown；长描述可展开/收起。编辑描述时默认显示「源码」，可切换到「预览」查看当前未保存草稿的完整 Markdown 效果；原始 HTML 不作为页面元素执行。日历详情和总览的事项卡片上有打印图标，已有事项的编辑弹窗底部也可「导出已保存事项」；新标签页展示完整事项，点击「打印 / 保存为 PDF」使用浏览器打印或另存 PDF。弹窗内未保存的修改不会出现在打印页。
5. 在描述中输入 `@`，按标题、项目名称或日期（含「未设日期」）筛选事项，点击候选或使用 ↑/↓、Enter 插入；Escape 仅收起候选，保留编辑弹窗。引用支持跨项目、跨日期和互相引用，每项最多 50 个不同目标，不能引用自身。
6. 日历详情和总览均展示描述内引用和「被引用」；日历中点击有日期引用会跳转到对应日期，无日期引用会打开总览定位；总览中的引用直接定位对应事项。跨项目时必要的筛选会清除。旧版本的独立引用继续展示，编辑时在「已有引用」中保留或单独移除。
7. 在「素材库」上传图片或通用文件，按文件名搜索或筛选图片/文件，切换网格／列表视图，重命名和下载原件。点击「N 个事项引用」在小窗中查看引用素材的事项，点击事项可跳转（含已完成和未设日期事项）；没有引用时计数不可点击。素材列表不显示 MIME 类型；图片列表和事项附件小图读取私有的压缩 WebP 缩略图，点开大图和打印时读取原图。普通文件限 20 MiB，可预览图片限 20 MB（图片转换服务的输入上限）；PNG、JPEG、GIF、WebP 图片支持预览，其余格式仅作为文件下载。事项编辑弹窗的「附件」可直接上传并添加，或从素材库选择已有文件；每个事项最多关联 50 个素材。素材与事项的关联在保存事项时生效；取消编辑不会删除已上传至素材库的文件。被事项引用的素材不能从素材库删除，请先在所有事项中移除关联。
8. 点击「我的空间」切换邮箱。删除事项会清理其两端引用及附件关联；删除项目会连同所属事项及相关关联一起删除，素材仍保留在素材库。

桌面月/周视图悬停或键盘聚焦事项，可查看包含标题、项目、日期、状态和描述的 tooltip；长内容可滚动，Escape 收起。月/周视图可拖动事项标签到可见的其他日期直接改期（月视图含前后月补位日期，周视图限当前七天）；保存失败会保留原日期并显示错误。周视图的手机端点按事项标题打开详情浮层，编辑仍从下方单日详情进入；手机月视图可横向滚动，显示每日事项数量和最多三个可拖动的标签。键盘操作可在编辑弹窗中修改日期。顶部项目栏可横向滚动。

在编辑弹窗和独立编辑标签页中，描述均支持「源码 / 预览」标签切换，也可聚焦标签后用左右方向键切换。预览包含尚未保存的修改与描述内引用，返回源码保留正文、选区和撤销记录；加密描述解锁后同样可预览。描述输入框随内容自动增高，长正文由弹窗或页面滚动。在正文中间输入、换行、替换选区及插入引用时保持当前编辑位置，光标、选区和撤销/重做沿用浏览器原生行为。

「从素材库选择」列表中的图片素材支持悬停或键盘聚焦时显示缩略图和文件名，编辑弹窗与独立编辑标签页共用。预览按需读取私有缩略图，Escape 仅收起预览；点击素材仍直接添加附件。图片加载失败时显示提示，仍可添加素材。

### 周期重复与复制事项

- 事项表单的所属项目、重复和修改范围共用 Nuxt UI 下拉选择组件，记录日期与截止日期共用日历选择器。浮层显示于编辑弹窗上层并适配可用空间，打开选择菜单保持表单容器高度；Escape 只收起当前选择浮层。需要开始日期的重复规则隐藏日期清除按钮，单次例外仍可以清除日期。
- 在新建或编辑普通事项的「重复」中选择 **每天 / 工作日 / 每周 / 每月 / 每年**。工作日为周一至周五；每周按开始日期的星期重复。必须设置开始日期与截止日期，截止当天包含在内。表单实时预览次数及前几个日期，一个系列最多 366 次；附件、引用与排期组合过大时，服务端提示缩短范围并保持原数据。
- 保存时将时间段内的每次排期作为真实、独立 ID 的事项保存到云端，日历可以提前查看，总览、搜索、引用、附件及打印沿用这些记录。各次默认未完成；创建时手动设置完成只作用于首条。勾选完成或拖动改期只影响本次，不影响后续出现。
- **不存在的日期必须在 modal 中确认后才保存**。每月 31 日遇到 2 月等短月时使用当月最后一天，之后恢复原始日号，例如 `1 月 31 日 → 2 月 28 日 → 3 月 31 日`；每年 2 月 29 日在非闰年使用 2 月 28 日，闰年恢复 2 月 29 日。modal 列出每个不存在的日期、替代日期与规则总次数；「返回修改」、关闭或 Escape 保留草稿，不写入云端。弹窗与独立编辑标签页共用此提醒。
- 编辑周期事项时，在「修改／删除范围」选择 **仅本次 / 本次及以后 / 整个系列**。「以后」以原始排期为准，即使该次已拖动、改期或清除日期仍定位同一排期。单次修改保留为例外；批量编辑保留各次完成状态和其他单次例外，只传播实际修改的字段。调整后续重复规则时拆分系列，并保留原始月日锚点，短月替代日期不会让后续日号漂移。
- 改变重复规则后，不再符合日期的未完成、未单独调整记录被移除；已完成、单次调整及正在编辑的记录保留为独立事项。选择「不重复」可将所选范围转为独立事项。单次删除保存排期跳过记录，刷新或延长截止日期不会重新生成已删除排期。范围删除会清理相应事项的引用与附件关联；删除项目清理所属实例，已单独迁移到其他项目的实例继续保留。
- 列表操作栏及已有事项编辑器提供 **复制**：从当前已读取的云端保存快照建立新草稿，保留标题、正文、项目、日期、主动引用和附件关联，默认未完成、不带重复系列；保存后创建新事项，附件继续关联素材库原文件。源事项的未保存修改不会进入副本；编辑器内复制前会确认丢弃未保存修改。副本可以再次设置重复，也可在新标签页编辑。
- 加密事项复制时保留加密状态与原密码，锁定时可直接复制密文；解锁后修改副本正文或更改密码按原加密流程保存。源事项与副本各自独立。创建重试复用稳定 ID，加密创建的同一草稿也复用已准备密文；已写入但响应丢失、或之后同步失败，不会重复生成整个系列。独立标签页同步确认后可继续编辑。

### 事项独立编辑标签页

- 在添加或编辑事项的弹窗右上角点击「在新标签页编辑」图标，使用与导出/打印相同的新标签页方式打开。日历详情（含日视图）和项目总览的事项列表，也可点击卡片右侧打印按钮旁的「在新标签页编辑」外链图标直接进入，支持无日期、已完成及加密事项。编辑页提供完整事项表单，包括 Markdown 源码与草稿预览、@ 引用、附件、完成状态与描述加密。
- **以云端已保存内容为准**。已有事项在新标签页重新读取云端；新建只带入默认项目、日期（日历保留选中日期，总览默认无日期）。从编辑弹窗打开时，如有未保存修改先确认，取消则保留原弹窗和草稿；修改后恢复原值、单纯解锁不会触发警告。新标签页成功加载并确认后关闭原弹窗，加载失败或被浏览器拦截时保留原输入。从列表直接打开不会出现编辑弹窗，也不改变工作台的日期、视图或筛选。
- **保存后保持打开**，显示保存与同步结果，可连续修改。首次新建成功后地址切换为该事项的编辑链接；写入成功但同步失败时保留内容并提供重试同步，确认前暂停继续写入，避免重复新建。写入失败保留草稿，可直接重试。删除成功后显示「事项已删除」。
- 支持同源通信时，新标签页在初始化时取得来源工作台的邮箱空间，随后自行读取数据；来源工作台切换邮箱或关闭不改变已打开编辑页的空间。直接访问编辑链接或刷新标签页时使用浏览器记住的邮箱，未记住时可以输入。邮箱、正文与密码不放入编辑 URL；临时通信标识在初始化时移除。
- 同一邮箱的工作台与独立编辑页在项目、事项或素材写入成功后通知彼此重新同步，保留各自的视图与筛选。后台读取不覆盖正在编辑的草稿；已读取到当前事项的云端变更时提示重新加载，并暂停保存，重新加载前确认未保存修改。不支持同源通信时可手动同步；从弹窗打开后可在新标签页加载完成时手动关闭原弹窗。列表入口打开失败时在工作台显示可关闭的提示。
- 当前事项已解锁时，新标签页可通过一次性密钥交接解锁**云端已保存正文**，弹窗与列表入口均适用。未保存正文及密码输入不会带入；各页面的解锁状态独立。连续编辑、改密保存后保持解锁，刷新则需重新输入密码；也可从独立编辑页导出已保存事项。
- 返回工作台前如有未保存修改会先确认；关闭或刷新独立编辑标签页时使用浏览器的未保存修改提示。手机窄屏下项目、日期及密码字段纵向排列，长描述由页面自然滚动。

### 可选描述加密

- 新建或编辑事项时勾选「加密描述」，输入并确认该事项的独立密码（8–256 个 UTF-16 单元，保留首尾空白）。默认关闭，已有事项不会自动加密；空描述也可加密。
- **仅加密描述正文**。标题、所属项目、日期、完成状态、添加时间、引用关系及附件仍按现有方式保存和展示；附件文件内容不加密。邮箱仍用于选择空间，加密密码不用于账户登录或限制事项的修改、删除。
- **保存成功并同步确认后保持解锁**：新建加密事项、首次启用加密、已解锁事项编辑，以及更改口令都适用，可以直接继续编辑或免口令导出打印。在日历详情、项目总览的事项卡片或编辑弹窗输入密码，点击「解锁描述」（也可按 Enter）查看锁定正文；解锁后恢复 Markdown、内联引用和展开/收起，悬浮预览共享当前页面的解锁结果。锁定时引用关系依然可见，解锁后内联引用不再重复显示在独立引用区。
- 原本锁定时可以修改标题、项目、日期、状态和附件，保存保留原密文、引用及锁定状态；修改正文、更改密码或取消加密前须先解锁。解锁后可点击「更改加密密码」，或取消勾选「加密描述」并保存为明文。取消编辑不改变已保存内容。
- 保存失败时草稿保留在编辑器，事项卡片继续显示已保存内容；写入成功但同步失败时，本次正文与密钥快照只在页面内存等待重试，读取到与保存响应一致的密文后才更新解锁缓存。主动锁定、切换邮箱或事项被删除/外部改密文会取消待更新的缓存；A→B→A 切换也不能复用旧保存操作的迟到结果。
- 点击「重新锁定描述」、刷新或切换邮箱会清除当前页面的解锁状态；同一密文的普通同步保留解锁，其他来源的密文变化或事项删除时清除。从当前已解锁的事项导出时，打印新标签页可自动解锁，无需再次输入口令；卡片和编辑弹窗的导出入口均适用，打印内容始终以已保存的记录为准。
- **打印页保持独立**：自动解锁完成后，工作台重新锁定、切换邮箱或关闭都不影响已打开的打印页；各打印页可以单独重新锁定。刷新打印页后需要再次输入口令。未解锁事项、直接访问打印链接或交接失败时仍可手动解锁，解锁前「打印 / 保存为 PDF」不可用。
- 免口令导出及打开已解锁事项的独立编辑标签页，通过一次性的同源 `BroadcastChannel` 交接不可导出的 `CryptoKey`，接收页核对邮箱、事项 ID 和完整密文指纹后自行解密。打印与编辑使用各自命名空间的随机通道，确认接收、30 秒超时或源页面状态失效后清理；URL fragment 中的临时通信标识在页面初始化时立即移除，不能独立解密正文。不支持通道或密钥克隆的浏览器沿用口令输入。
- 使用浏览器原生 Web Crypto：**AES-256-GCM**（128-bit 标签、随机 12-byte IV），**PBKDF2-SHA-256 / 600,000 次**（随机 16-byte 盐）派生不可导出的密钥。每次重新加密生成新 IV，新设密码生成新盐；版本固定算法与派生参数。正文先序列化为 JSON 字符串再加密，保留完整 UTF-16 内容，支持最多 20,000 个 UTF-16 单元。
- 密码、密钥和解密正文只保存在使用它们的页面内存，不发送给 API、不写入 localStorage / sessionStorage，也不通过打印 URL 传递；打印交接只传递密钥对象及记录身份信息，不传口令或明文正文。云端保存版本、盐、IV 和密文。忘记密码无法恢复描述，请妥善保管；加解密需要 HTTPS 或 localhost 及支持 Web Crypto 的浏览器。

### 描述与引用格式

普通和加密描述上限均为 **20,000 个 UTF-16 单元**（JavaScript `string.length`，例如 `😀` 占 2 个），包含引用标记本身。选择候选会在源码中插入稳定 ID 标记：

```text
准备工作参考 @[首页设计](item:123e4567-e89b-12d3-a456-426614174000)，然后完成本次迭代。
```

- 这是专用引用语法，不是普通 Markdown 链接；在正文和 Markdown 列表中可跳转，在代码中保持字面文本。标题中的 `\`、`[`、`]`、换行、回车分别转义为 `\\`、`\[`、`\]`、`\n`、`\r`；ID 为 1–64 个字母、数字、下划线或连字符。实际新建事项使用 UUID。
- 普通邮箱、普通 `@` 文本和不完整标记不会生成引用。标记前不能紧接 ASCII 单词/邮箱字符或反斜线；优先用候选插入，避免手工构造。
- 引用按 ID 关联，同名事项仍是不同目标；目标改名后显示当前标题。删除目标会清理引用关系，原描述标记保留并显示「已删除」。
- 保存时将有效标记中的目标去重，并与未被手动移除的旧引用合并，过滤自身和已不存在的目标。删除标记会移除该引用；旧引用一旦转为描述标记，随后删除标记也会移除关系。

## 数据库开发约定

数据库访问统一使用 **Drizzle ORM** 的 D1 驱动：

- `apps/api/src/db/schema.ts` 定义账户、项目、事项、引用、素材、事项附件和 R2 待清理记录的类型化映射、索引及约束；`completed` 使用 boolean 模式映射 SQLite 整数。
- `apps/api/src/db/index.ts` 的 `createDb` 是 D1 binding 到 ORM 实例的统一入口。业务查询、计数和增删改使用 ORM API，查询条件保留当前邮箱范围。
- 事项及引用通过 ORM 的 `db.batch` 一起写入，底层使用 D1 原子批处理。每个引用分别构造插入语句，避免 50 个引用合并插入时超过 D1 单语句参数上限。
- 数据库建表与升级由 Wrangler 应用 `apps/api/migrations/` 中的 SQL 迁移；`0001_initial.sql` 建表，`0002_entry_description.sql` 增加非空描述列，旧记录默认 `''`；`0003_optional_entry_date.sql` 将日期改为可空，重建事项表前备份并移除引用表，再恢复引用和索引，避免外键级联丢失引用。数据模型调整需同步更新 schema 和新增迁移。
- 当前未接入 Drizzle Kit 增量迁移生成；后续接入时需以现有数据库的实际约束和索引建立基线。
- `0004_project_sort_order.sql` 增加项目 `sort_order` 列；旧项目默认 0，仍按创建时间和 ID 保持原顺序。排序接口通过 Drizzle batch 原子更新全部项目位置；API 返回的项目数组已排序，排序值属于内部存储字段。
- `0005_assets.sql` 增加素材元数据、事项附件关联及 R2 删除重试表；复合外键限制邮箱，素材在被事项引用时不可删除。原文件和首次读取时按需生成的 320px WebP 缩略图均位于私有 R2，数据库仅存元数据和原文件对象键；删除时先以 D1 批处理移除元数据并记录两个待清理键，再删除 R2 对象，失败可在下次上传/删除时重试。重命名仅修改数据库名称，不影响原文件和引用。
- `0006_encrypted_description.sql` 增加可空的 `encrypted_description` JSON 文本列；已有明文数据保留。数据库约束禁止密文与非空明文描述共存；事项、密文、引用和附件关联使用同一个 Drizzle batch 保存。
- `0007_recurring_entries.sql` 增加系列规则、版本写入记录、跳过排期及事项系列/原始日期/例外字段；系列外键级联、唯一排期索引及同邮箱触发器保护实例归属。实例与关联原子生成，版本写入记录在同一事务内拒绝并发覆盖。普通旧事项新增字段为默认值，API 仅为周期实例额外返回 `recurrence`。

## Cloudflare 部署

部署结构：**一个 Cloudflare Worker（Static Assets 前端 + `/api/*`）→ D1 + 私有 R2 + Images binding**。图片首次请求缩略图时通过 Images binding 转换并写入 R2，后续读取已存储的缩略图；图片转换会计入 Cloudflare Images 用量。本地 Wrangler 提供离线图片转换。页面、JS/CSS 和接口共用一个域名、一次部署；不再需要 Pages 项目。下面的命令会创建或更新远程资源。

### 1. 创建 D1 并配置 Worker

使用 workspace 中已安装的 Wrangler 登录；已有 `agenda-db` 时复用现有数据库，仅新环境需要创建：

```sh
bun run --cwd apps/api wrangler login
# 仅首次创建数据库时执行
bun run --cwd apps/api wrangler d1 create agenda-db
# 仅首次创建素材桶时执行
bun run --cwd apps/api wrangler r2 bucket create hoshinos-agenda-assets
```

将创建结果中的数据库 ID 写入 `apps/api/wrangler.jsonc`：

- `d1_databases[0].database_id`：填写上述命令返回的数据库 ID；使用现有配置时确认其对应目标数据库。
- `d1_databases[0].binding`：保留 `DB`，与 API 代码一致。
- `r2_buckets[0]`：确认 `ASSETS` binding 对应刚创建的 `hoshinos-agenda-assets` 桶。部署 Worker 前须确保目标账号中已经存在此桶；本地 Wrangler 模拟无需远程桶。
- `assets.directory`：指向 Nuxt 静态生成目录；`run_worker_first` 将 `/api` 和 `/api/*` 交给 API，防止浏览器直接访问接口时返回 SPA HTML。其他页面路径使用 SPA 回退。
- `vars.ALLOWED_ORIGINS`：保持空字符串即可，同源请求自动允许。如需额外跨域客户端，仍支持逗号分隔的来源和 `*` 通配符，例如 `https://tools.example.com,https://*.example.com`；匹配整个 Origin，返回实际 Origin。该配置不用于解决 Access 的跨域认证。
- Worker 名称暂沿用 `hoshinos-agenda-api`，因此会更新原 Worker；现在这个 Worker 同时承载前端。D1 ID 与已有迁移保持兼容。

### 2. 一次部署前端和 API

**先建 R2 桶并应用 D1 迁移（至 `0007_recurring_entries.sql`），再部署**；已有数据库同样需要检查迁移：

```sh
bun run db:migrate:remote
bun run deploy
```

`deploy` 先生成前端，再由 Wrangler 一起上传 Worker 和静态资源。以后更新前端或 API 都运行这条命令；`deploy:api` 作为兼容别名也会执行完整部署。本地迁移与远程迁移是独立操作。

部署输出的 Worker 地址（例如 `https://hoshinos-agenda-api.YOUR_SUBDOMAIN.workers.dev`）即可打开完整应用；同一地址的 `/api/health` 返回 JSON。无需设置前端 API 地址或执行 `wrangler pages deploy`。

### 3. 域名与 Cloudflare Access

1. 在 Worker 的 **Settings → Domains & Routes** 添加自定义域名，例如 `agenda.example.com`。若该域名原本绑定 Pages，先解除旧绑定，再绑定到 Worker。
2. 在 Cloudflare Zero Trust 的 Access 应用中保护整个 `agenda.example.com`，覆盖页面与 `/api/*`，使用同一套访问策略。登录后浏览器同源请求会自动携带 Access Cookie，无需跨域预检放行或单独登录 API 域名。
3. 若保留 `workers.dev` 或预览 URL 入口，也应为其启用对应的 Access 保护；不需要的入口可在 Worker 设置中禁用。
4. 移除旧 Pages 的自动部署任务及 `NUXT_PUBLIC_API_BASE` 配置；新域名验证成功后可停用旧 Pages 项目。

访问正式域名，验证 Access 登录、项目和事项的创建/修改、素材上传/预览/下载、刷新后数据保留及邮箱切换。浏览器 Network 中页面与 API 应属于同一个 Origin。更换域名无需重新生成 API 地址或修改 CORS 列表。数据库或素材错误则检查 D1 ID、`DB`/`ASSETS` binding、R2 桶及远程迁移。

Access 会话过期时仍需重新登录（刷新页面即可进入认证流程）。应用内邮箱继续用于选择数据空间，并未改为 Access 身份映射。

除健康检查和 OPTIONS 预检外，所有请求需携带 `X-User-Email`；写入请求使用 `Content-Type: application/json`。错误统一返回 `{"error":"说明"}`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | Worker 健康检查 |
| GET | `/api/agenda` | 当前邮箱全部项目、事项（含引用和素材 ID）及素材元数据（含引用次数） |

| GET | `/api/assets/:id/content` | 按当前邮箱读取私有文件；图片内联，其他文件作为附件下载 |
| GET | `/api/assets/:id/thumbnail` | 按当前邮箱读取图片的私有 WebP 缩略图；首次请求按需生成，非图片返回 404 |
| PATCH | `/api/assets/:id` | 重命名素材：JSON `{ "name": "新文件名" }`；保留文件内容与关联 |
| DELETE | `/api/assets/:id` | 删除未被事项引用的素材；被引用时返回 409 |
| POST | `/api/projects` | 创建项目：`name`、`color` |
| PUT / DELETE | `/api/projects/:id` | 修改或级联删除项目 |
| PUT | `/api/projects/order` | 保存项目顺序：`projectIds`（新顺序）、`previousIds`（页面加载的原顺序） |
| POST | `/api/entries` | 创建事项 |
| PUT | `/api/entries/:id` | 修改事项及引用 |
| PATCH | `/api/entries/:id` | 仅更新 `completed` |
| DELETE | `/api/entries/:id` | 删除事项及两端引用 |

事项输入字段为必填的 `title`、`projectId`、`date`（`YYYY-MM-DD` 或 `null`）、`completed`（布尔值）、`references`（事项 ID 数组），以及可选的 `description`（字符串）和 `assetIds`（当前邮箱的素材 ID 数组，最多 50 个，自动去重）。POST 缺省 `assetIds` 为空，PUT 缺省时保留已有素材关联；显式传 `[]` 则清空。项目名称上限 64 字符，事项标题上限 200 字符；项目颜色支持六位 HEX RGB，`shared/types.ts` 的 `PROJECT_COLORS` 提供预设颜色。

项目排序的两个字段均为无重复 ID 数组；新顺序必须完整包含当前邮箱所有项目，缺失、重复或其他邮箱 ID 返回 400，原顺序与读取到的当前顺序不符返回 409。校验失败不写入。所有位置在一个批处理中保存，项目内容、事项及引用保持不变。

- `date: null` 表示未设日期，POST/PUT 都需显式传入 `date`；省略、空字符串、非字符串/非 null 或无效日期返回 400。GET 返回字符串或 `null`；PATCH 可单独提交 `date` 或 `completed`，仅修改指定字段，不能在同一请求中同时修改两者。
- `description` 不 trim，允许空字符串，最多 **20,000 个 UTF-16 单元**；`null`、非字符串或超长返回 400。描述不能替代必填标题。
- POST 与 PUT 的 `description` 缺省均规范化为 `''`；**PUT 缺省会清空原描述**。PATCH 完成状态不会修改描述。校验失败时事项及引用保持不变。
- GET `/api/agenda` 的每个事项均返回字符串 `description`；POST/PUT 成功返回 `{ id, description }`。
- JSON 请求体按实际 UTF-8 字节计量，上限 **256 KiB（262,144 字节，含 JSON 转义、Base64 密文及其他字段）**，超过返回 413；恰好 262,144 字节仍可接受。素材上传是单独的二进制接口，实际请求流限 **20 MiB**，空文件拒绝；不信任文件名中的路径或图片声明，未验证的图片作为普通附件下载。文件读取始终校验邮箱并返回 `no-store`，R2 桶无需开放公共访问。
- 素材名称去除首尾空格，最多 255 字符，不允许控制字符或路径分隔符；重命名后下载文件名同步更新。损坏或无法解码的图片在生成缩略图时返回 422，不自动以原图代替缩略图；已上传的原文件仍可下载。
- API 将描述作为纯文本存储，引用关系以显式 `references` 为准，不从描述自动创建关系；自定义客户端需要同时提交引用 ID。服务端继续校验引用属于当前邮箱、存在、不是自身，原始数组最多 50 项，再去重。前端仅将已获 API 引用关系的有效标记显示为可跳转引用。

加密事项额外提交 `encryptedDescription: { version: 1, salt, iv, ciphertext }`，三个二进制字段使用规范的带 padding Base64。版本 1 的密文是上述 JSON 字符串的 AES-GCM 结果（含标签），认证附加数据为 UTF-8 `agenda:description:v1`。服务端验证字段、版本、盐/IV 长度及密文字节上限（120,018 字节，Base64 最多 160,024 字符），不持有密码或解密正文；加密事项必须将 `description` 省略或设为 `''`，同时提交非空明文会返回 400（整个请求体超限时优先返回 413）。引用与附件 ID 仍显式提交，不从密文推导。

- GET 和 POST/PUT 的成功响应在加密时额外返回 `encryptedDescription`，`description` 始终为 `''`；明文事项省略此字段，保持原客户端响应兼容。
- 取消加密时显式提交 `encryptedDescription: null` 和明文 `description`。已有加密事项的 PUT 若省略加密字段，返回 409 且不写入，防止旧客户端误清空密文；锁定编辑应原样提交密文。普通明文事项仍沿用原有缺省描述清空规则。
- PATCH 日期或完成状态不改变密文；描述的 20,000 UTF-16 单元限制由加密客户端及解密时校验，API 对密文校验加密后大小，请求体总上限为 256 KiB。

所有查询及写入通过 Drizzle ORM 按 `owner_email` 限定范围，复合外键保证项目、事项和引用属于同一邮箱。事项与引用在同一 ORM/D1 batch 内写入，反向引用由前端推导。日期作为日历日期处理，不使用 UTC 截断计算本地「今天」。

### 周期事项 API

- 沿用 `/api/entries` 创建接口，可额外提交 `recurrence: { frequency, startDate, until }`，`frequency` 为 `daily / weekdays / weekly / monthly / yearly`，两个日期为有效 `YYYY-MM-DD`，开始日期须与 `date` 一致。工作日开始于周末时，首条为范围内第一个工作日。缺少截止、无可用日期或超过 366 次返回 400。
- 有短月或闰年替代时，必须提交 `acknowledgeAdjustments: true`，否则返回 409。`anchorDate` 是可选有效日期，用于拆分月/年系列后保留原始月日；前端及服务端按同一规则展开并提示替代明细。
- GET 的周期实例额外返回 `recurrence: { seriesId, scheduledDate, exception, rule, version }`；普通事项省略。系列保存响应额外包含 `savedEntry`，用于独立编辑页核对服务端实际保存快照；普通首写保持既有响应格式。
- PUT / DELETE `/api/entries/:id` 支持 `scope: 'single' | 'following' | 'all'`，默认 `single`；批量操作必须提交读取到的 `seriesVersion`，版本过期返回 409 且整批保持不变。DELETE 的范围参数使用 JSON 请求体。PUT 可提交新 `recurrence`，或用显式 `null` 将范围转为独立事项；省略规则时保留原规则。PATCH 的日期与完成仍只作用于单次。
- POST 的可选 `requestId` 为稳定、1–64 位字母/数字/下划线/连字符创建 ID；同一 ID 与相同内容的重试返回既有记录，不再生成实例。不同内容重用 ID 返回 409。前端只在同一新草稿生命周期复用；UUID 是默认值。
- `tests/recurrence.spec.ts` 验证日期展开、366 次边界、真实 D1 幂等创建、并发版本保护、三种范围、例外和级联；桌面/手机验证 modal、取消和失败重试、月末后续锚点、复制的附件/引用/加密、响应丢失及独立页面保存确认。
